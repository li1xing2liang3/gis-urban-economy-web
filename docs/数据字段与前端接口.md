# 数据字段与前端接口

本文档用于约束前端读取的静态数据与未来后端接口，便于从当前 mock 数据平滑替换到 GeoJSON、OGC 服务或 PostGIS API。

## 通用约定

- 坐标系：GeoJSON 默认使用 WGS84，经纬度顺序为 `[lng, lat]`。
- 时间字段：统一使用 `YYYY-MM-DD` 或 `YYYY-MM` 字符串。
- 数据版本：通过全局 `ds` 参数标识，例如 `v2026Q1`、`v2025Q4`、`demo-mix`。
- 数据来源：界面图层使用 `智眼`、`无人机`、`POI`、`多源`、`模型`、`演示` 六类标签；若为模拟数据，必须在元数据或图层说明中注明。

## 前端数据服务

当前统一入口位于 `web/src/services/gisDataService.ts`。开发环境默认访问 `/api`，由 `web/vite.config.ts` 代理到 `http://127.0.0.1:8787` 的 mock API；若后端不可用，会回退到静态 mock 数据。

| 方法 | API / 兜底文件 | 用途 |
| --- | --- | --- |
| `getHealth()` | `/api/v1/health` | 后端健康检查 |
| `getDataSources()` | `/api/v1/hubei/metadata/data-sources` / `public/data/mock/hubei/api-fixtures.json` | 数据源元数据 |
| `getLayerCatalog()` | `/api/v1/hubei/metadata/layers` / `public/data/mock/hubei/api-fixtures.json` | 图层目录 |
| `getCityUnits()` | `/api/v1/hubei/geo/city-units?ds=v2026Q1` / `public/data/mock/hubei/city-units.geojson` | 武汉功能片区、活力、人口、消费等分级属性 |
| `getPoiSample()` | `/api/v1/hubei/poi/sample?ds=v2026Q1` / `public/data/mock/hubei/poi-sample.geojson` | 武汉 POI 样点、业态、重要度 |
| `getPoiInfluence()` | `/api/v1/hubei/poi/influence?ds=v2026Q1` / `public/data/mock/hubei/poi-influence.geojson` | 武汉 POI 主商圈圆形影响区 |
| `getProvinceTimeseries()` | `/api/v1/hubei/timeseries/province?ds=v2026Q1` / `public/data/mock/hubei/timeseries-wuhan.json` | 武汉月度人口、经济、活力等趋势 |
| `getCityTimeseries()` | `/api/v1/hubei/timeseries/cities?ds=v2026Q1` / `public/data/mock/hubei/timeseries-cities.json` | 武汉片区级时序扩展 |
| `getZhiyanObservations()` | `/api/v1/hubei/sensing/zhiyan-observations?ds=v2026Q1&date=2026-04-08` / `public/data/mock/hubei/api-fixtures.json` | 武汉智眼型感知观测点 |
| `getUavRoutes()` | `/api/v1/hubei/uav/routes?ds=v2026Q1` / `public/data/mock/hubei/uav-routes.json` | 武汉无人机航线、覆盖质量、智眼参考联动 |
| `getUavCoverages()` | `/api/v1/hubei/uav/coverages?ds=v2026Q1` / `public/data/mock/hubei/api-fixtures.json` | 武汉无人机覆盖面 |
| `getLatestVitalityModel()` | `/api/v1/hubei/models/vitality/latest` / `public/data/mock/hubei/api-fixtures.json` | 最新活力模型结果 |
| `getLatestDistrictModel()` | `/api/v1/hubei/models/districts/latest` / `public/data/mock/hubei/api-fixtures.json` | 最新商圈识别结果 |
| `runVitalityModel(payload)` | `POST /api/v1/hubei/models/vitality/run` / 静态 latest 结果合成 | 触发活力模型 |
| `runDistrictModel(payload)` | `POST /api/v1/hubei/models/districts/run` / 静态 latest 结果合成 | 触发商圈识别 |

后续接真实后端时，优先保持这些方法名不变，仅替换后端实现或代理地址。

## 三维城市展示

三维城市页位于 `web/src/views/Scene3DView.vue`。当前页面保留本地可运行的 Cesium 建筑白模、经济指标着色、低空航廊与无人机三维航线动画；暂不展示未配置的外部 3D Tiles 入口，避免项目演示时出现不可用功能。

若后续拿到稳定的武汉实景三维服务，应优先由后端代理鉴权与跨域，再在服务层中接入，不直接把政务密钥写入前端环境变量。

## city-units.geojson

每个 Feature 建议包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 区域名称 |
| `tier` | number | 层级或核心等级 |
| `tierLabel` | string | 层级说明 |
| `vitalityIdx` | number | 经济活力指数，0~100 |
| `nightEconomyIdx` | number | 夜间经济指数，0~100 |
| `consumePotential` | number | 消费潜力指数，0~100 |
| `inboundFlowIdx` | number | 客流吸引指数，0~100 |
| `popDensity` | number | 人口密度示意值 |

## poi-sample.geojson

每个点 Feature 建议包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | POI 名称 |
| `category` | string | 中文业态 |
| `categoryKey` | string | 英文字段，如 `retail`、`food`、`office` |
| `cityName` | string | 所属城市或区域 |
| `importance` | number | 重要度，0~1 |

## uav-routes.json

每条无人机路径建议包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 航线唯一标识，可写入 URL 的 `uav` 参数 |
| `name` | string | 航线名称 |
| `district` | string | 重点观测区域 |
| `scene` | string | 任务场景，如夜间经济、三维建模、通勤观测 |
| `status` | string | 已入库、待复核、规划中等 |
| `time` | string | 采集或计划时间 |
| `altitude` | number | 飞行高度，单位米 |
| `speed` | number | 飞行速度，单位 m/s |
| `res` | string | 影像分辨率或模型等级 |
| `quality` | number | 路径/覆盖质量，0~100 |
| `zhiyanSync` | boolean | 是否参考智眼型人车热力触发 |
| `model` | boolean | 是否参与活力/商圈模型 |
| `overlay` | boolean | 是否默认地图叠加 |
| `waypoints` | `[lat, lng][]` | 航点数组，Leaflet 绘制使用纬经顺序 |
| `imageUrl` | string | 航线关联真实影像预览地址，位于 `public/data/uav-images` |
| `imageTitle` | string | 影像标题 |
| `imageCredit` | string | 影像来源署名 |
| `imageLicense` | string | 许可或引用说明 |
| `imageSource` | string | 原始来源链接 |

说明：`waypoints` 是前端绘制格式；若后续改为 GeoJSON LineString，服务层应统一转换为该格式，避免页面逻辑变化。

低空无人机页面会将 `waypoints` 归一化到真实影像预览区域，在影像上叠加航线、航点、进度轨迹和无人机动画标记。该效果是面向项目展示的路径仿真，不代表真实飞控视频回放。

## API 接口约定

- `GET /api/v1/hubei/geo/city-units?ds=v2026Q1`
- `GET /api/v1/hubei/poi/sample?ds=v2026Q1&category=retail,food`
- `GET /api/v1/hubei/poi/influence?ds=v2026Q1&category=retail,food`
- `GET /api/v1/hubei/timeseries/province?ds=v2026Q1`
- `GET /api/v1/hubei/metadata/data-sources`
- `GET /api/v1/hubei/metadata/layers`
- `GET /api/v1/hubei/uav/routes?ds=v2026Q1&region=jianghan`
- `GET /api/v1/hubei/uav/coverages?ds=v2026Q1`
- `GET /api/v1/hubei/sensing/zhiyan-observations?ds=v2026Q1&date=2026-04-08`
- `GET /api/v1/hubei/models/vitality/latest`
- `GET /api/v1/hubei/models/districts/latest`
- `POST /api/v1/hubei/models/vitality/run`
- `POST /api/v1/hubei/models/districts/run`

模型接口返回应包含 `taskId`、`status`、`message`、`resultLayerId` 和可解释摘要，供任务条与图层树联动。
