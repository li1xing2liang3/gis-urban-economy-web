# 空间总览界面总结

> 路由：`/overview` · 组件：`web/src/views/OverviewView.vue`  
> 演示范围：**武汉市区**（非全省）  
> 最后更新：2026-06

---

## 一、页面定位

空间总览是平台的**默认首页**，承担「一屏看清武汉经济空间」的职责：在统一地图上叠加地形、建筑、道路、POI、活力等多源图层，并支持区域筛选、分析对比与结果导出。

与全局框架的关系：

| 模块 | 作用 |
|------|------|
| `GlobalContextBar` | 时间、数据源、区域模式（全市/行政区/点选/框选） |
| `gisState` | 全局状态写入 URL query，跨页面共享 |
| `LayerTreePanel` | 图层可见性、透明度、ℹ 说明 |
| 分析任务条 | 分析/识别类操作入队，可标记「已保存」 |

## 四、操作模式（三档）

KPI 条右侧 **选择 / 分析 / 对比** 与地图、KPI 联动。

### 4.1 选择（默认）

- 地图正常浏览，POI 全量显示（若图层开启）
- KPI 标签为「全局」

### 4.2 分析

- 按 `gis.region` **过滤 POI**：区域外 POI 不显示，区域内高亮
- 侧栏 `RegionStatsCard` 与 KPI 使用 **区域内 POI 聚合**（`overviewRegionStats.ts`）
- 自动向任务条推送「总览区域分析」任务
- 顶栏出现绿色提示条

### 4.3 对比

- 需顶栏时间模式为 **A/B 对比**，并选择 `timeCompareA` / `timeCompareB`
- 行政区 choropleth 按 **两期活力差值** 着色（红升、绿降）
- 提示条显示 A/B 数值与 Δ
- 若未配置对比日期，提示用户去顶栏设置

## 五、区域交互（与顶栏联动）

| 区域模式 | 地图行为 |
|----------|----------|
| 全市 | 无额外覆盖物 |
| 行政区 | 高亮区面 + `fitBounds`；切换区名即时刷新 |
| 点选 | 地图点击落点 + **1 km** 圆 |
| 框选 | 按住拖拽矩形；写入 `gis.region.box` |

框选实现：`attachBoxDraw()` 在 `mousedown/move/up` 时临时禁用拖拽。

区域统计（非全市）：活力值、POI 数、夜经济/消费潜力等，数据来自 `aggregateRegionKpis()`。

## 六、图层体系（8 层）

配置：`web/src/config/layerCatalog.ts` → `overviewLayerCatalog`

| ID | 名称 | 默认可见 | 数据来源 | 实现要点 |
|----|------|----------|----------|----------|
| `dem` | DEM / 地形 | 否 | 本地 `HillShadeWH.tif` | `L.imageOverlay`，读 `hillshade.meta.json` 范围 |
| `buildings` | 建筑高度 | **是** | Overture | **视口分区 + 缩放分级**（见第七节） |
| `roads` | 道路网络 | **是** | OSM 导出 GeoJSON | 优先 `roads.geojson`，回退 `roads-demo.geojson` |
| `poi` | POI 商业 | 否 | Mock 1035 点 | 点 + 圆形影响区，Canvas 渲染 |
| `pop` | 人口密度 | 否 | 行政区 mock | 区面 choropleth |
| `uav` | 无人机影像 | 否 | Mock 覆盖多边形 | 异步 `gisDataService` |
| `zhiyan` | 智眼热力 | 否 | Mock 观测点 | 异步加载 |
| `vitality` | 经济活力 | **是** | 模型 + 区 mock | 区面 choropleth，默认主视觉层 |

图层树支持：勾选可见、透明度滑条（0–1）、ℹ 弹层说明。

## 七、建筑图层优化（重点）

### 问题

全量 `buildings.geojson` 约 **123 MB / 40 万条**，一次性加载会导致页面卡死。

### 方案

1. **离线分块**：9 块 parquet → 三级 GeoJSON 瓦片  
   - 路径：`web/public/geo/wuhan/buildings/{low,mid,high}/tile_r_c.geojson`  
   - 索引：`manifest.json`（含每块 bounds 与统计）

2. **缩放分级**

   | 精度 | 缩放 | 几何处理 |
   |------|------|----------|
   | low | 12–13 | 强简化（≈180 m 容差） |
   | mid | 14–15 | 中等简化 |
   | high | ≥16 | 原始轮廓 |
   | （不加载） | <12 | 侧栏提示放大 |

3. **视口加载**：仅 fetch 与当前 `map.getBounds()` 相交的分区（通常 1–4 块）

4. **性能**：Canvas 渲染、内存缓存、moveend/zoomend debounce 200 ms

### 相关脚本

```bash
# 下载 Overture 建筑（9 块 parquet）
py -3.10 scripts/download-overture-wuhan-buildings.py

# 合并全量（可选备份）
py -3.10 scripts/download-overture-wuhan-buildings.py --merge-only

# 生成 Web 分级瓦片
py -3.10 scripts/prepare-wuhan-building-web-tiles.py
# 或 cd web && npm run prepare:wuhan-buildings
```

### 相关代码

- `web/src/utils/wuhanBuildingTiles.ts` — manifest、视口计算、fetch 缓存  
- `OverviewView.vue` — `refreshBuildingsTiles()` / `syncBuildingsLayer()`

## 十二、推荐使用流程

1. 启动：`cd web && npm run dev`，打开 `/overview`
2. 顶栏选择 **数据源、时间、区域**（如「江汉区」或框选光谷）
3. 默认可见：**经济活力** + **建筑** + **道路**
4. 需要地形：勾选 **DEM / 地形**
5. 看 POI：勾选 **POI 商业**，可切换 **分析** 模式看区域内过滤
6. 做对比：顶栏开 A/B 日期 → 点 **对比** → 看差值着色与提示条
7. 看建筑：缩放 **≥12**，拖动地图；侧栏可见当前精度与分区数
8. 导出：截图 / 报告 / 图层书签

| 文档 | `docs/交互功能说明.md` 中总览章节仍部分写「湖北省界」，以本文为准 |
