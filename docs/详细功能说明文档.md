# 城市低空经济空间展示平台详细功能说明文档

> 适用对象：项目汇报、答辩展示、验收说明、后续开发交接。  
> 文档版本：**v2.1**（与 `web/src` 当前实现一致，含**应用群**与多无人机协同调度子应用）。  
> 项目范围：本**应用群**以**武汉市**为研究范围，围绕城市低空经济、经济活力、商圈识别、人口消费、经济动态、单机/多机无人机航线与协同调度仿真进行 WebGIS 展示。  
> 数据说明：当前项目采用**武汉范围空间数据 + 开放数据/仿真数据 + Mock API/静态文件**支撑演示流程，不宣称接入武汉智眼真实生产库或实时视频流。

## 1. 项目概述

### 1.1 平台定位

“城市低空经济空间展示平台”是一个面向武汉市低空经济场景的 AI+GIS 可视化**应用群**。主平台将二维地图、三维城市、经济空间分析和单机无人机航线仿真结合起来；**多无人机协同调度应用**作为独立子应用，扩展为编队级任务分配、空域协同与多机三维回放演示。

平台主要解决以下问题：

- 低空经济航线如何和城市商业、物流、文旅、应急等经济场景结合。
- 城市经济活力、商圈、人流、消费潜力如何在地图中直观展示。
- 无人机路径如何在城市建筑与 DEM 地形环境中进行可视化模拟。
- 在单机航线基础上，如何用**多机协同调度**演示错峰起飞、高度分层与冲突消解。
- 在缺少真实生产数据时，如何用仿真数据完成完整的前端功能闭环。

### 1.2 技术形态

| 二维地图 | Leaflet |

| 数据范围 | 武汉市 |
| 接口模式 | 优先请求后端 API；不可用时回退本地 mock 数据 |
| 展示方式 | 同一 SPA 内的**应用群**：主平台（首页 + 七个专题模块）+ 编队调度独立子应用 |

## 2. 技术栈详细说明

### 2.1 技术栈总览

本项目采用“前端单页应用 + 本地静态数据/Mock API + 可扩展真实后端”的技术路线。核心思路是先保证展示平台在本地能够完整运行，再通过统一数据服务逐步替换为真实接口。

| 技术类别 | 使用技术 | 项目作用 |
|---|---|---|
| 前端框架 | Vue 3 | 构建页面组件、响应式状态和交互逻辑 |
| 构建工具 | Vite | 本地开发服务、模块热更新、生产构建 |
| 开发语言 | TypeScript | 提供类型约束，降低数据结构和地图对象使用错误 |
| 路由管理 | Vue Router | 管理应用群路由：主平台七专题 + 编队调度三页 |
| 二维地图 | Leaflet | 实现 WebGIS 二维地图、图层叠加、点线面渲染 |
| 三维场景 | Cesium | 实现三维城市、建筑白模、无人机三维航线 |
| 三维构建插件 | vite-plugin-cesium | 解决 Cesium 在 Vite 中的静态资源和模块加载问题 |
| 截图导出 | html2canvas | 将空间总览地图区域导出为图片 |
| 空间数据格式 | GeoJSON | 存储武汉边界、道路、建筑、POI、航线等空间数据 |
| 专题数据格式 | JSON | 存储人口消费、经济动态、模型结果、DEM 元数据等 |
| 地形数据 | DEM / hillshade PNG | 表达地形起伏和低空净空分析背景 |
| 接口联调 | Vite proxy + Mock API | 前端请求 `/api` 时代理到本地后端或回退静态数据 |
| 数据生成脚本 | Node.js / Python | 生成仿真数据、DEM 预览、武汉地理预览数据 |

### 2.2 前端框架：Vue 3

Vue 3 是本项目的核心前端框架，负责组织页面、组件、状态和交互逻辑。

**项目中的使用方式**

- 每个功能页面对应一个 Vue 单文件组件，例如：
  - `HomeView.vue`：首页。
  - `OverviewView.vue`：空间总览。
  - `Scene3DView.vue`：三维城市。
  - `VitalityView.vue`：经济活力。
  - `BusinessDistrictView.vue`：商圈识别。
  - `PopulationView.vue`：人口消费。
  - `DynamicsView.vue`：经济动态。
  - `LowAltitudeView.vue`：低空数据（单机航线）。
  - `fleet/FleetAppHomeView.vue`、`FleetDispatchWorkspaceView.vue`、`FleetScenariosView.vue`：多机协同调度子应用。
- 使用 `ref`、`reactive`、`computed`、`watch` 管理页面状态。
- 使用组件拆分公共功能，例如图层树、全局上下文条、分析任务条、区域统计卡片。

**选择原因**

- Vue 适合快速构建交互式数据展示平台。
- 组件化结构清晰，便于把地图、图表、控制面板拆开维护。
- 响应式机制适合处理图层开关、时间轴播放、权重调整等实时 UI 变化。

### 2.3 构建工具：Vite

Vite 负责本地开发服务器和生产构建。

**项目中的配置**

- 默认开发端口：`5173`。
- API 代理：前端请求 `/api` 时会代理到 `http://127.0.0.1:8787`。
- 路径别名：`@` 指向 `web/src`，方便导入组件和工具模块。
- Cesium 插件：通过 `vite-plugin-cesium` 支持三维资源加载。

**常用命令**

| 命令 | 作用 |
|---|---|
| `npm run dev` | 启动前端开发服务 |
| `npm run build` | 构建生产版本 |
| `npm run preview` | 预览生产构建结果 |
| `npm run generate:mock-wuhan` | 生成武汉 mock 数据 |
| `npm run generate:sim-wuhan` | 生成扩展仿真数据 |
| `npm run generate:dem-wuhan` | 生成武汉 DEM 相关资产 |
| `npm run prepare:wuhan-geospatial` | 准备武汉地理预览数据 |

### 2.4 开发语言：TypeScript

项目使用 TypeScript 编写主要逻辑，并开启较严格的类型检查配置。

**项目中的作用**

- 为 GIS 状态、图层配置、无人机航线、DEM 元数据、模型结果等定义类型。
- 减少 GeoJSON、Leaflet 图层、Cesium 对象使用时的字段错误。
- 让前后端接口字段更加清晰，方便后续接真实 API。

**相关目录**

| 目录 | 说明 |
|---|---|
| `web/src/types/` | 项目类型定义 |
| `web/src/services/` | 数据服务与接口类型 |
| `web/src/stores/` | 全局 GIS 状态 |
| `web/src/utils/` | 数据生成、模型、地图工具函数 |

### 2.5 路由系统：Vue Router

Vue Router 用于管理单页应用的页面切换。

**路由结构**

**主平台**

- `/`：首页。
- `/overview`：空间总览。
- `/scene3d`：三维城市。
- `/vitality`：经济活力。
- `/districts`：商圈识别。
- `/population`：人口消费。
- `/dynamics`：经济动态。
- `/lowaltitude`：低空数据。

**编队调度子应用**（`FleetDispatchLayout`）

- `/fleet-dispatch`：应用首页。
- `/fleet-dispatch/workspace`：调度工作台。
- `/fleet-dispatch/scenarios`：协同方案库。
- `/uav-fleet` → 重定向至 `/fleet-dispatch/workspace`。

**项目特点**

- 首页与编队应用首页独立展示，不套用 `MainLayout`。
- 七个功能页共用 `MainLayout`，保持导航、顶栏和底栏统一。
- 编队应用使用独立顶栏/底栏与配色，可通过链接返回主平台。
- 全局 GIS 状态会写入 URL query（主平台）；编队工作台支持 `?scenario=` 深链载入方案。

### 2.6 二维 WebGIS：Leaflet

Leaflet 是本项目二维地图的核心库，主要承担基础地图、图层叠加、点线面绘制和交互操作。

**主要应用页面**

- 空间总览。
- 经济活力。
- 商圈识别。
- 人口消费。
- 经济动态。
- 低空数据中的二维预览图。

**实现能力**

| 能力 | 说明 |
|---|---|
| 底图加载 | 使用 OSM 等瓦片底图 |
| 武汉边界 | 加载 `wuhan-boundary.geojson` 并缩放到武汉范围 |
| 点图层 | POI、航点、热力中心点 |
| 线图层 | 道路网络、无人机航线 |
| 面图层 | 城市片区、商圈、人口密度、覆盖范围 |
| Canvas 渲染 | 道路、建筑等较多要素使用 Canvas 降低卡顿 |
| 地图交互 | 缩放、平移、点击、框选、弹窗、tooltip |

**性能处理**

- 道路图层使用预览数据而不是全量超大文件。
- 建筑图层按视口分区加载。
- 高密度矢量图层尽量使用 Canvas renderer。
- 不可用图层会自动跳过，避免白屏。

### 2.7 三维 GIS：Cesium

Cesium 是本项目三维城市和低空无人机仿真的核心技术。

**主要应用页面**

- 三维城市与经济空间（`/scene3d`）。
- 多无人机协同调度工作台（`/fleet-dispatch/workspace`，`useCesiumUavFleet`）。
- 低空页（`/lowaltitude`）以航拍影像 + SVG 动画及 Leaflet 预览为主；单机三维漫游请跳转三维城市页。

**实现能力**

| 能力 | 说明 |
|---|---|
| 三维地球/地图 | 提供三维空间浏览能力 |
| 建筑白模 | 使用本地建筑体块表达城市空间 |
| 经济着色 | 按经济活力或功能属性给建筑着色 |
| 三维航线 | 使用空间点和高度生成无人机路径 |
| 飞行模型 | 使用飞机形状图标沿 Cesium 时钟驱动航路运动（无第一人称相机跟随） |
| 预设视角 | 一键定位商圈、CBD（枢纽视角）、低空航线 |

**后续扩展**

- 接入真实 3D Tiles。
- 接入 Cesium ion OSM Buildings。
- 接入更精细的建筑高度、禁飞区和空域数据。
- 接入真实无人机遥测数据回放。

### 2.8 截图导出：html2canvas

html2canvas 用于把页面中的地图和分析结果导出为图片。

**当前应用**

- 空间总览页面的“截图导出”功能。
- 导出文件名为 `overview-map.png`。

**价值**

- 方便做 PPT。
- 方便保存当前图层组合。
- 方便形成阶段分析成果。

### 2.9 数据服务层：gisDataService

`gisDataService` 是前端访问数据的统一入口，避免各页面直接散乱请求文件或接口。

**调用策略**

1. 若配置真实 API 地址，则优先请求后端。
2. 若后端不可用，则自动回退本地 mock 数据。
3. 页面只关心数据结果，不需要关心数据来自后端还是静态文件。

**主要读取内容**

- 城市片区、活力格网、POI 样本与影响区。
- 全省/市州时序（`getProvinceTimeseries` / `getCityTimeseries`）。
- 无人机航线与覆盖面、智眼型观测点。
- 数据源元数据、图层目录。
- 活力/商圈模型 latest 与 run 接口。

> DEM 山体阴影以静态 PNG 加载；部分专题仍直接读 mock 静态 JSON。服务层尚未暴露独立 DEM 剖面 API。

**优势**

- 演示时没有后端也能运行。
- 后续接入真实服务时，不需要大规模改页面。
- 有利于统一字段和错误处理。

### 2.10 全局状态管理：自定义 GIS Store

项目没有引入 Pinia 或 Vuex，而是使用 Vue 的 `reactive` 自定义了轻量级 GIS 全局状态。

**管理内容**

- 当前时间。
- 时间模式。
- A/B 对比日期。
- 当前区域。
- 当前数据源。
- 无人机是否参与模型。
- 当前选中航线。
- 经济活力结果。
- 商圈识别结果。
- 分析任务列表。

**特点**

- 结构轻量，不增加额外依赖。
- 与 Vue Router 同步，可写入 URL。
- 足够支撑当前演示平台的跨页面联动。

### 2.11 空间与专题数据格式

项目主要使用 GeoJSON 和 JSON 两类数据格式。

**GeoJSON 用途**

- 武汉市边界。
- 道路网络。
- 建筑轮廓。
- POI 点。
- 商圈识别面。
- 无人机航线。
- 无人机覆盖范围。
- 风险区或任务区。

**JSON 用途**

- 人口消费仿真数据。
- 经济动态小时级数据。
- 模型运行结果。
- DEM 元数据。
- 无人机任务记录。
- 数据源元信息。
- 图层目录。

**为什么适合本项目**

- 浏览器可直接读取。
- 便于和 Leaflet、Cesium 对接。
- 字段结构清晰，适合后续迁移到 PostGIS 或后端 API。

### 2.12 数据生成与预处理脚本

项目包含若干脚本，用于生成或整理演示数据。

## 3. 全局功能

### 3.1 顶部信息栏

**功能作用**

顶部信息栏用于展示平台品牌、当前页面标题、演示环境标识、系统时间等内容，是所有核心页面共用的全局区域。

**主要内容**

- 平台名称：AI+GIS 城市低空经济驱动的城市经济空间展示平台。
- 当前页面标题：根据路由自动切换。
- 环境标识：演示。
- 当前时间：用于增强平台运行感。

**汇报说明**

顶部信息栏体现平台不是单一地图页面，而是一个统一的城市经济空间分析系统。

### 3.2 左侧导航栏

**功能作用**

左侧导航栏提供七个核心模块入口，支持在不同专题功能之间快速切换。

**导航模块**

- 空间总览
- 三维城市
- 经济活力
- 商圈识别
- 人口与消费
- 经济动态
- 低空数据

**交互行为**

- 点击导航项切换页面。
- 当前页面导航项高亮。
- 侧栏可收起，便于展示地图和三维场景。

### 3.3 全局上下文筛选

**功能作用**

全局上下文筛选用于统一管理时间、区域和数据源。不同页面切换时，这些状态可以保持一致，便于跨页面联查。

**筛选内容**

| 筛选项 | 说明 |
|---|---|
| 时间模式 | 单日、区间、播放、A/B 对比 |
| 单日时间 | 用于活力、人口、动态等专题 |
| 时间区间 | 用于趋势和时序分析 |
| A/B 时间 | 用于经济动态对比 |
| 区域范围 | 全市、行政区、点选、框选 |
| 数据版本 | v2026Q1、v2025Q4、演示混编等 |

**不在顶栏、但写入 URL 的联动项**

| 控件位置 | 说明 | URL 键 |
|---|---|---|
| `/vitality`、 `/lowaltitude` | 无人机参与活力模型 | `pops` |
| `/lowaltitude` | 选中航线 ID | `uav` |
| `/dynamics` | 双时间 A/B 对比开关 | `cmp` |
| `/population` | A/B 区名 | `popA` / `popB` |
| `/districts` | 选中商圈 | `did` |

**技术实现**

全局状态保存在 `gisState` 中，由 `useGisRouterSync` 写入 URL query（约 100ms debounce）。主要键：

| 键 | 含义 |
|---|---|
| `t` | 单日时间 |
| `t0` / `t1` | 时间区间起止 |
| `ta` / `tb` | A/B 对比日期 |
| `tm` | 时间模式（single / range / play / compareAB） |
| `r` | 区域（全市 / 行政区 / 点选 / 框选） |
| `ds` | 数据源版本 |
| `uav` | 选中无人机航线 ID |
| `pops` | 无人机是否参与活力模型 |
| `cmp` | 经济动态双时间对比 |
| `popA` / `popB` | 人口页 A/B 区名 |
| `did` | 选中商圈 ID |

**价值**

- 方便跨页面同步同一组分析条件。
- 方便汇报时通过 URL 保留当前状态。
- 为后续真实后端接口联动预留参数。

### 3.4 分析任务条

**功能作用**

分析任务条用于展示模型运行、路径分析、低空航线规划等任务状态。

**任务状态**

- 运行中（RUN）
- 完成（OK）
- 失败（ERR）
- 已固化（PERSISTED，点击「固化」后）

**使用场景**

- 经济活力模型运行。
- 商圈识别任务执行。
- 无人机路径质检。
- 低空航线规划发布。

**汇报价值**

任务条让平台更像真实业务系统，而不是静态展示页，能够体现“提交任务 -> 计算分析 -> 输出结果”的工作流。

## 7. 经济活力与商业分析

### 7.1 功能定位

### 7.2 指标逻辑

当前演示模型采用多因子加权方式。指标包括：

| 指标 | 说明 |
|---|---|
| 人流热度 | 权重滑条可调，表达区域人群活动强度 |

## 11. 低空数据增强中心

### 11.1 功能定位

低空数据增强中心是平台的特色模块，用于展示面向低空经济应用的无人机航线、路径优化、航拍影像飞行仿真、低空云处理演示和模型联动。

### 11.2 经济场景

航线规划不仅展示飞行路径，还与经济主题相关：

| 场景 | 说明 |
|---|---|
| 夜间消费商圈 | 服务江汉路、两江四岸等夜间经济区域巡检 |
| 站城枢纽物流 | 服务武汉东站、交通枢纽周边低空配送与监测 |
| 产业园巡检 | 服务光谷、开发区等产业空间 |
| 江滩文旅航线 | 服务沿江文旅、活动保障和客流观测 |
| 应急保障 | 服务突发事件巡查和重点区域复核 |

### 11.3 核心能力

- 无人机航线列表（含航拍影像 `imageUrl`）。
- 航线质量、状态、分辨率、速度、高度展示。
- **航线真实影像飞行仿真**：航拍底图 + SVG 航迹/航点/飞机模型动画。
- Leaflet 地图预览：航线叠加、覆盖面、航点 Marker。
- 参与活力/商圈模型开关（与 `/vitality` 联动）。
- 路径优化三策略：安全巡航 / 覆盖优先 / 效率优先。
- 低空云处理四阶段演示流程。
- 生成路径分析任务。
- 跳转三维城市、空间总览、经济活力页面。
- 跳转 **多无人机协同调度应用**（`/fleet-dispatch`）。

### 11.4 页面组成

| 区域 | 内容 |
|---|---|
| 中央主视觉 | 航线真实影像 + SVG 飞行仿真（播放/暂停、进度条） |
| 侧栏·路径优化 | 三策略 Tab、预计航程/时长/覆盖率/风险等指标 |
| 侧栏·地图预览 | Leaflet 航线叠加、定位按钮 |
| 侧栏·低空云处理 | 四阶段进度、提交任务、云指标 |
| 侧栏·航线列表 | 名称、状态、质量、参与模型复选 |
| 侧栏·跨页链接 | 三维视点、二维总览、经济活力 |

### 11.5 路径优化逻辑

当前航线优化为前端演示算法，主要包括：

- 按经济场景增加关键节点。
- 对商圈、枢纽、产业区等经济锚点进行路径贴合。
- 对路径拐角进行平滑或简化（依策略）。
- 输出**预计航程、时长、覆盖率、风险等级、航程变化**等指标。

### 11.6 飞行仿真逻辑

**本页（`/lowaltitude`）**

- 中央：选中航线的航拍影像上叠加 SVG 航迹、航点与飞机形无人机，支持播放/暂停与进度条。
- 侧栏地图：Leaflet 显示航线 polyline、覆盖面与沿路径移动的 Marker。

**三维城市页（`/scene3d`）**

- Cesium 时钟驱动无人机沿三维航路运动（含航廊、安全包络、下视传感器锥演示）。
- 无第一人称相机跟随；需沉浸式三维效果时使用预设「低空航线」视角。

### 11.7 路径优化指标说明

应用优化策略后，侧栏展示下列**已实现**指标：

| 指标 | 说明 |
|---|---|
| 预计航程 | 优化后路径长度（km） |
| 时长 | 按航线速度估算（min） |
| 覆盖率 | 演示合成覆盖百分比 |
| 风险 | 低 / 中低 / 中（依策略） |
| 航程变化 | 相对原始航线的百分比变化 |

> **后续扩展**：基于 DEM 的最低/最高地面高程、最小净空等剖面分析，当前版本未单独成 panel。

## 12. 多无人机协同调度应用

### 12.1 功能定位

编队调度子应用面向**城市低空经济多机并行任务**演示：在单机航线能力（`/lowaltitude`）之上，展示**任务分配、空域协同规则、协同时序编排与多机三维回放**，与主平台形成「经济空间分析 + 低空运行调度」的应用群闭环。

### 12.2 与主平台关系

| 维度 | 主平台 `/lowaltitude` | 编队应用 `/fleet-dispatch` |
|---|---|---|
| 粒度 | 单机航线规划与影像仿真 | 多机编组、错峰、冲突消解 |
| 布局 | `MainLayout` 七专题之一 | 独立 `FleetDispatchLayout` |
| 数据 | `uav-routes` 等 | `uav-fleet-dispatch-plan`、telemetry、registry、conflicts |
| 联动 | 活力模型 UAV 因子 | 仿真下发写入 `gis.tasks`；四机方案完成可回写 `uavQualityBoost` |

### 12.3 预置协同方案（Mock）

| 方案 ID | 名称 | 规模 | 策略 |
|---|---|---|---|
| `scenario-jianghan-optics-dual` | 江汉—光谷双机错峰巡检 | 2 架 | 时间错峰 + 高度分层 |
| `scenario-river-triple` | 两江四岸三机协同观测 | 3 架 | 分区负责 + 中心协调 |
| `scenario-vitality-sync` | 活力模型联动四机编队 | 4 架 | 优先级队列 + 模型回写 |

### 12.4 调度工作台能力

- **方案切换**：侧栏与方案库载入；URL `?scenario=` 深链。
- **协同仿真回放**：统一时钟驱动 Gantt、二维轨迹进度、倍速与进度条拖拽。
- **双视图**：二维协同 SVG 预览 / Cesium 多实体同步（`useCesiumUavFleet`）。
- **控制台**：机队编组、协同规则、冲突消解记录（时刻高亮）。
- **任务下发**：进入调度阶段自动 `pushTask`；完成后 `updateTask` 成功态。

### 12.5 数据文件与接口

| 文件 / 接口 | 内容 |
|---|---|
| `uav-fleet-dispatch-plan.json` | 编队方案、schedule、rules、metrics |
| `uav-fleet-registry.json` | 机型、续航、就绪度 |
| `uav-fleet-telemetry.json` | 统一时钟 tracks + frames |
| `uav-fleet-conflicts.json` | 冲突类型、间隔、消解说明 |
| `GET /api/v1/wuhan/uav/fleet-dispatch-plans?ds=v2026Q1` | 方案 API |
| `GET /api/v1/wuhan/uav/fleet-telemetry?ds=v2026Q1` | 遥测 API |
| `GET /api/v1/wuhan/uav/fleet-registry?ds=v2026Q1` | 机队 API |
| `GET /api/v1/wuhan/uav/fleet-conflicts?ds=v2026Q1` | 冲突 API |

生成脚本：`web/scripts/generate-wuhan-simulation-extension.mjs`（`npm run generate:sim-wuhan`）。

### 12.6 演示说明与边界

**可完整演示：** 方案库浏览 → 载入工作台 → 播放协同仿真 → 切换三维 → 查看冲突消解与任务队列。

**演示级限制（汇报须说明）：** 调度结果为预生成 JSON，无运行时冲突重算；不支持自定义编组编辑；与 vitality 页为单向权重回写，非实时双向联动。

### 13.2 接口调用策略

前端通过 `gisDataService` 统一读取数据。逻辑为：

1. 如果配置了 `VITE_API_BASE_URL`，优先请求后端 API。
2. 如果后端不可用或请求失败，自动回退到本地 mock 数据。
3. 保证演示环境中即使没有后端服务，前端页面仍然可以运行。

### 13.3 主要接口类型

> 接口命名空间为 `/api/v1/hubei/`（历史兼容）；业务展示范围聚焦**武汉市**，与路径前缀无矛盾。

| 接口类型 | 示例 |
|---|---|
| 健康检查 | `/api/v1/health` |
| 数据源/图层元数据 | `/api/v1/hubei/metadata/data-sources`、`/api/v1/hubei/metadata/layers` |
| 城市片区 | `/api/v1/hubei/geo/city-units?ds=v2026Q1` |
| 活力格网 | `/api/v1/hubei/geo/vitality-grid?ds=v2026Q1` |
| POI 样点/影响区 | `/api/v1/hubei/poi/sample?ds=v2026Q1` |
| 时序 | `/api/v1/hubei/timeseries/province?ds=v2026Q1` |
| 智眼型观测 | `/api/v1/hubei/sensing/zhiyan-observations?ds=v2026Q1&date=…` |
| 无人机航线/覆盖面 | `/api/v1/hubei/uav/routes?ds=v2026Q1` |
| 多机编队方案/遥测/冲突 | `/api/v1/wuhan/uav/fleet-*?ds=v2026Q1` |

完整清单见 [前后端API连接设计.md](./前后端API连接设计.md)。

### 13.4 数据真实性说明

汇报中建议使用以下表述：

> 本项目以武汉市为研究范围，采用开放空间数据与自构造仿真数据复现城市感知数据结构，实现低空经济空间展示和模型分析流程。武汉智眼类数据在本项目中作为指标体系参考，不作为真实生产数据来源。
