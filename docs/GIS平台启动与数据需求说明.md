# GIS 平台：前端启动说明与数据需求

本文档面向**第一次使用**本项目的同事，分三部分：**如何打开网页前端**、**湖北省界数据如何生效与维护**、**为完成各功能需要准备哪些数据**。

---

## 第一部分：如何打开前端页面（零基础分步）

### 1. 你需要先安装什么？

在电脑上安装 **Node.js**（长期支持版即可）。

1. 打开浏览器，访问：**https://nodejs.org/**
2. 下载 **LTS（长期支持）** 安装包（Windows 选 `.msi`）。
3. 双击安装，一路「下一步」即可（可勾选 “Add to PATH”）。
4. 安装完成后**重新打开**终端（或重启 Cursor），否则可能识别不到命令。

**如何确认装好了？**

- 按键盘 `Win + R`，输入 `cmd` 回车，打开「命令提示符」。
- 输入下面两行（每行回车），若都显示版本号（数字）即正常：

```text
node -v
npm -v
```

若提示「不是内部或外部命令」，说明未加入环境变量或未重启终端，请重新安装或重启电脑后再试。

---

### 2. 前端代码在哪个文件夹？

本仓库里，**网页前端的工程目录**是根目录下的 **`web`** 文件夹（若你本机路径为 `e:\GIS project`，则完整路径为 `e:\GIS project\web`）。

**说明文档**集中在 **`docs`** 目录（本文件即位于 `docs/GIS平台启动与数据需求说明.md`）。

后面所有命令，要么在 `web` 目录里执行，要么使用下面「一条命令启动」里从仓库根目录调用的方式。

---

### 3. 第一次：安装依赖（只需做一次，或改过依赖后再做）

**方法一：用 Cursor / VS Code 的终端（推荐）**

1. 用 Cursor 打开文件夹 `e:\GIS project`。
2. 菜单 **终端 → 新建终端**（或快捷键 `` Ctrl+` ``）。
3. 在终端里**逐行**输入下面命令（每行末尾按回车）：

```powershell
Set-Location "e:\GIS project\web"
npm install
```

等待结束，没有大量红色报错即可（末尾可能有 `npm audit` 提示，可暂忽略）。

**说明：** 路径里有空格，所以**必须**给路径加英文双引号 `"..."`。

---

### 4. 启动网页（每次要看页面时做）

在上一步已经 `Set-Location` 到 `web` 目录的前提下，输入：

```powershell
npm run dev
```

**成功时**，终端里会出现类似：

```text
  VITE v5.x.x  ready in xxx ms
  ➜  Local:   http://localhost:5173/
```

这表示开发服务器已启动。

---

### 5. 用浏览器打开页面

1. 打开 **Chrome / Edge** 等浏览器。
2. 在地址栏**完整输入**（或复制粘贴）：

**http://localhost:5173/**

3. 回车。

**若打不开：**

- 确认上一步终端里 `npm run dev` **仍在运行**（不要关掉该终端窗口，也不要按 `Ctrl+C`）。
- 确认地址是 **5173** 端口（本项目在 `vite.config.ts` 里配置的端口）。
- 若公司网络限制外网，底图（OpenStreetMap）可能较慢，但页面框架应能出来。

---

### 6. 不想先切换目录时（一条命令）

在**任意**终端当前路径下，可直接执行：

```powershell
npm --prefix "e:\GIS project\web" run dev
```

然后在浏览器同样打开：**http://localhost:5173/**

---

### 7. 停止服务

在运行 `npm run dev` 的那个终端窗口里，按 **`Ctrl + C`**，再按 `Y` 确认（若提示），即可停止。

---

### 8. 常见错误（PowerShell）

- **提示 `&&` 无效**：说明当前 PowerShell 版本较旧。请不要写 `cd xxx && npm install`，改用**两行**，或一行里用**分号**：

```powershell
Set-Location "e:\GIS project\web"; npm install
```

## 第二部分：湖北省 Shapefile 已如何接入、你如何更新

### 1. 仓库里的两份数据（职责不同）

| 位置 | 作用 |
|------|------|
| **`data/geospatial/boundaries/hubei-province/`** | **权威数据源**：放置中文文件名的 `湖北省.shp` 全套（`.shx`、`.dbf`、`.prj` 必需；`.cpg`、`.sbn`、`.sbx` 可选）。适合版本管理、在 QGIS 中编辑。 |
| **`web/public/geo/hubei/hubei.*`** | **给浏览器用**：由脚本从上一行目录**复制**而来，文件名统一为 **`hubei`** 前缀（避免 URL 中文编码问题）。 |

程序实际请求的是：`/geo/hubei/hubei.shp` 等（由 `shpjs` 按不含扩展名的 URL 前缀自动拼接扩展名）。

### 2. 从数据源同步到前端（克隆或更新省界后执行）

在**仓库根目录**打开终端，执行其一即可：

```bash
node scripts/sync-hubei-to-web-public.mjs
```

或在 **`web`** 目录下：

```powershell
npm run sync:geo
```

执行后应看到 `hubei.shp`、`hubei.dbf` 等写入 `web/public/geo/hubei/`。

### 3. 地图上的效果

所有使用 **Leaflet 二维地图**的页面（总览、活力、商圈、人口、动态、低空等）在加载时，会**自动请求** `public` 下的 shapefile，解析为 GeoJSON 后叠加**湖北省边界**（蓝色描边、浅蓝填充），并**自动缩放到全省范围**（`maxZoom` 限制为约 9 级，避免过近）。

若文件缺失或损坏，控制台会打印警告，地图会退回**以武汉为中心的默认缩放**。

### 4. 你以后更新了省界数据，要怎么做？

1. 用 QGIS / ArcGIS 等导出新的 shapefile（仍建议 WGS84 经纬度，与 `湖北省.prj` / `hubei.prj` 一致可减少问题）。
2. **覆盖** `data/geospatial/boundaries/hubei-province/` 下的 `湖北省.*` 文件。
3. 在仓库根目录执行 **`node scripts/sync-hubei-to-web-public.mjs`**（或 `web` 下 **`npm run sync:geo`**）。
4. 刷新浏览器；若 `npm run dev` 未在运行，需重新启动后再访问。

## 第三部分：数据需求说明（需要哪些数据、支撑哪些功能）

下列与《GIS前端页面设计说明》（见 **`docs/GIS前端页面设计说明.md`**）及当前前端路由**一一对应**。坐标系建议统一为 **CGCS2000 / WGS84（EPSG:4326 经纬度）**；栅格切片常用 **Web 墨卡托（EPSG:3857）** 或与底图一致。

### 1. 全局与基础设施

| 数据/能力 | 用途 | 与功能的关系 |
|-----------|------|----------------|
| 底图服务（XYZ/WMTS） | 道路、水系、注记 | 全部地图页可视底图；当前演示为 OSM，生产可换合规图源。 |
| 省 / 市 / 区行政界 | 范围、统计单元、裁剪 | **已接入省界**；市界、区界、街道界用于更细粒度 KPI 与裁剪。 |
| 统一空间参考与元数据 | 叠加不出错、可审计 | 所有图层；需记录：现势性、来源、坐标系、分辨率、更新周期。 |
| 后端 API + 空间库（如 PostGIS） | 存矢量栅格、模型结果 | 书签、截图、模型任务、权限等落地时必需。 |

### 2. 按页面列数据需求

#### 页面 1：城市经济空间总览（`/overview`）

| 功能点 | 需要的数据 |
|--------|------------|
| 多图层开关与透明度 | 各专题的 **切片或矢量服务地址** + 图例配置（分级颜色、单位）。 |
| 经济活力分布（模型结果） | **活力指数栅格/矢量**（全市或全省范围、带时间可选）。 |
| DEM / 建筑 / 道路 / POI / 人口 / 无人机 / 智眼热力 | 对应 **DEM、建筑体块或轮廓高度、路网、POI 点、人口栅格/分区、影像切片、热力栅格**（可为占位服务，逐步替换）。 |
| 视图书签、导出截图 | 书签：视域、图层状态序列化 + 后端存储；截图：前端 canvas 或地图服务出图接口。 |

#### 页面 2：三维城市与经济空间（`/scene3d`）

| 功能点 | 需要的数据 |
|--------|------------|
| 地形 | **DEM** 或三维地形服务；若用 Cesium World Terrain 等需合规账号与 token。 |
| 建筑白模 / 精模 | **带高度的建筑矢量** 或 **3D Tiles / glTF** 服务地址。 |
| 无人机三维成果 | **mesh 或 3D Tiles** + 元数据（范围、时间、分辨率）。 |
| 经济指标贴建筑 | **建筑 ID 与指标表**（或空间连接后的属性表），按时间切片。 |

#### 页面 3：经济活力与商业分析（`/vitality`）

| 功能点 | 需要的数据 |
|--------|------------|
| 模型输入 | **人流/活动（如智眼）**、**POI 密度**、**交通可达性**（路网 + 阻抗）、可选 **无人机观测指标**。 |
| 模型参数版本 | 各数据源 **版本号与起止时间**，便于复现。 |
| 模型输出 | **网格/分区活力指数**（GeoJSON/栅格/WMS），及统计摘要（直方图、TOP 区）。 |

#### 页面 4：商圈识别与结构地图（`/districts`）

| 数据 | 用途 |
|------|------|
| 商业 POI 点 | 聚类输入；需 **类别、名称、坐标、时间**。 |
| 算法参数与运行记录 | 阈值、最小样本等存于业务库。 |
| 输出商圈面 | **商圈多边形** + 属性（名称、置信度、主导业态、人流量摘要等）。 |

#### 页面 5：人口密度与消费潜力（`/population`）

| 数据 | 用途 |
|------|------|
| 人口分布 | **人口栅格** 或 **街道/社区面 + 人口字段**；多期需带 **时间**。 |
| 消费潜力 | **潜力分级结果**（与人口、收入、业态等模型一致的分级标准说明）。 |
| 对比分析 | 至少两套区域或两期数据，支持统计对比。 |

#### 页面 6：经济动态与时序分析（`/dynamics`）

| 数据 | 用途 |
|------|------|
| 人流 / 车流时序 | **按小时或更细粒度** 的空间切片（栅格或六边形等），与 **时间轴** 联动。 |
| 昼夜 / 节假日模式 | **日历标注**（节假日名称）、典型日分类。 |
| 动态图例 | 全时间域的 **数值范围** 或分位数，保证跨帧可比。 |

#### 页面 7：低空数据增强中心（`/lowaltitude`）

| 数据 | 用途 |
|------|------|
| 正射 / 倾斜影像 | **WMTS/XYZ** 或切片包 URL，**覆盖范围多边形**。 |
| 航线 | **LineString** 矢量 + 航高、时间、传感器。 |
| 三维模型 | 与页面 2 一致的 **3D 数据** 或链接。 |
| 参与模型标志 | 业务字段：**是否参与活力/商圈模型**。 |

#### 应用 B：多无人机协同调度（`/fleet-dispatch`）

| 数据 | 用途 |
|------|------|
| `uav-fleet-dispatch-plan.json` | 编队方案、schedule、协同规则、metrics |
| `uav-fleet-telemetry.json` | 统一时钟 tracks / frames，驱动 Gantt 与回放 |
| `uav-fleet-registry.json` | 机型、续航、就绪度，合并至编组展示 |
| `uav-fleet-conflicts.json` | 冲突类型、间隔、消解说明 |
| 关联单机航线 | `uav-routes` 中的 `routeId`，与低空页数据族一致 |

生成命令：`cd web && npm run generate:sim-wuhan`。入口：首页、低空页、或直接访问 `/fleet-dispatch`。

### 3. 「武汉智眼」类感知数据（跨页面）

| 数据内容 | 支撑功能 |
|----------|----------|
| 实时或准实时人流/车流热力 | 总览热力、动态页时间轴、活力模型输入。 |
| 历史切片 | 周期对比、节假日 vs 平日。 |
| 接入方式 | 消息流、REST 定时拉取或 **时空数据库 + WMS/WMTS**；需说明延迟与覆盖范围。 |

### 4. 低空与无人机（特色模块）

| 数据 | 支撑功能 |
|------|----------|
| 无人机影像、点云/mesh | 低空页、三维页、精细尺度活力辅助 |
| 单机航线 `uav-routes` | `/lowaltitude` 影像仿真与模型联动 |
| 编队 `uav-fleet-*` | `/fleet-dispatch` 多机协同调度演示 |
| 观测元数据 | 分辨率、航向、重叠度、处理报告，用于质检与展示 |

### 5. 数据交付建议格式（便于与前后端对齐）

| 类型 | 建议格式 |
|------|----------|
| 行政界、商圈、网格 | **GeoJSON**（<10MB）或 **矢量瓦片（MVT/PBF）** + PostGIS |
| 大范围栅格 | **COG GeoTIFF**、**WMTS/XYZ** |
| 三维 | **3D Tiles**、**glTF** |
| 表格指标 | **CSV/Parquet** + 与空间要素 **关联键** |
| 接口 | **REST JSON** + 可选 **OGC**（WMS/WMTS/WFS） |
