# 经济活力界面总结

> 路由：`/vitality` · 组件：`web/src/views/VitalityView.vue`  
> 演示范围：**武汉市区**（非全省）  
> 最后更新：2026-06

---

## 一、页面定位

经济活力页是平台的**多因子活力评估专题**，承担「可调权重、即时重算、格网 + 行政区双尺度展示」的职责：在统一地图上叠加 750m 活力格网、行政区汇总面、POI、智眼观测与低空因子，并支持权重滑条、后端模型运行与结果分解。

与全局框架的关系：

| 模块 | 作用 |
|------|------|
| `GlobalContextBar` | 时间、数据源、区域模式（全市/行政区/点选/框选） |
| `gisState.vitality` | 活力模型结果全局持久，跨页面共享 |
| `LayerTreePanel` | 5 层图层可见性、透明度、ℹ 说明 |
| 分析任务条 | 「经济活力」「同参重算」入队，可标记完成/失败 |

## 四、活力评估模型

### 4.1 四因子权重

| 因子 | 默认权重 | 侧栏控件 | 数据来源 |
|------|----------|----------|----------|
| 人流 | 0.35 | 滑条 0–1 | 行政区属性 + `timeseries-cities.json` |
| POI 商业 | 0.30 | 滑条 0–1 | 同上 |
| 交通 | 0.25 | 滑条 0–1 | 同上 |
| 无人机 | 0.10 | 滑条 + 复选框 | 低空页航线/覆盖 + `uavQualityBoost` |

权重经 `normalizeWeights()` 归一化；拖动滑条 **即时重绘** 地图与右栏，无需点击运行。

### 4.2 得分公式（本地）

核心逻辑：`web/src/utils/vitalityModel.ts`

1. **因子混合**：`footTrafficIdx` / `poiActivityIdx` / `trafficReachIdx` 与当月时序 65:35 混合  
2. **综合得分**：`vitalityIdx × 0.28 + 加权因子 × 0.52`  
3. **时序修正**：`vitalityAtMonth()` 按选中日期再混合 72:28  
4. **数据源系数**：v2026Q1 ×1.03、v2025Q4 ×0.97、混编 ×1.0  
5. **无人机加成**（勾选时）：`score × (1 + uavQualityBoost × 0.12 × …)`  
6. 输出 **0–100** 整数，配色 `vitalityFillColor()`

格网单元额外按 `localRatio` 与所属区基期活力比做时序缩放（`computeGridVitalityScore`）。

### 4.3 运行模式

| 按钮 | 行为 |
|------|------|
| 重新运行 / 全量 | 调用 `gisDataService.runVitalityModel()` → 写 `gis.vitality` |
| 同参重算 | 本地 380ms 模拟任务，不请求后端 |
| 重置 | 恢复默认权重、图层、专题名 |

后端失败时保留本地热力结果，任务条标记 `MODEL_API_FAILED`。

## 五、区域交互（与顶栏联动）

| 区域模式 | 地图行为 |
|----------|----------|
| 全市 | 格网/区面全量显示 |
| 行政区 | 高亮区面虚线边框 + 区外格网/区面 **淡化** |
| 点选 | 1 km 绿色圆 |
| 框选 | 橙色矩形 |

非全市时右栏显示 `RegionStatsCard`（活力、POI 数、夜经济等），数据来自 `aggregateRegionKpis()`。

点击格网/区面或 TOP6 排名行 → 选中片区高亮（金色描边）并 `fitBounds`。

## 六、图层体系（5 层）

配置：`web/src/config/layerCatalog.ts` → `vitalityLayerCatalog`

| ID | 名称 | 默认可见 | 数据来源 | 实现要点 |
|----|------|----------|----------|----------|
| `vitality-grid` | 活力评估格网（750m） | **是** | 模型生成 | 3908 格，Canvas 渲染，点击弹窗分项指标 |
| `vitality-model` | 行政区汇总面 | 否 | `city-units.geojson` | 10 区 choropleth，tier 控制描边粗细 |
| `vitality-poi` | 商业 POI 样点 | 否 | Mock 1035 点 | 点 + 影响圆，按区域过滤 |
| `vitality-zhiyan` | 智眼型热力（模拟） | 否 | Mock 观测点 | 异步 `getZhiyanObservations()` |
| `uav-factor` | 低空观测因子 | **是** | 无人机覆盖 + 航线 | 需勾选「纳入无人机项」才参与得分 |

地图左下角固定 **综合活力** 渐变色条图例（蓝→青→黄→橙）。

## 七、750m 活力格网（重点）

### 生成方法

脚本：`web/scripts/generate-hubei-mock-datasets.mjs`（`buildVitalityGrid` 段）

| 步骤 | 说明 |
|------|------|
| POI 核密度 | 业态权重 × 重要度 × 高斯衰减 |
| 热点叠加 | 12 个核心商圈/节点高斯叠加 |
| 交通廊道 | 轨道交通/快速路可达性加权 |
| 区级基线 | 与 `city-units` / `timeseries-cities` 因果链一致 |
| 空间平滑 | 3×3 邻域双遍平滑 |

元数据：`web/public/data/mock/hubei/vitality-grid-meta.json`

| 项 | 值 |
|----|-----|
| 格网数量 | 3908 |
| 格元尺寸 | 约 749m × 684m |
| 参考月份 | 2026-04 |
| 主要字段 | `vitalityIdx`、`localRatio`、`hotspotLabel`、`vitalityClass` |

### 重新生成

```bash
cd web && node scripts/generate-hubei-mock-datasets.mjs
# 产物：public/data/mock/hubei/vitality-grid.geojson + vitality-grid-meta.json
```

## 十一、推荐使用流程

1. 启动：`cd web && npm run dev`，打开 `/vitality`
2. 顶栏选择 **数据源、时间、区域**（如「洪山区」）
3. 默认可见：**750m 格网** + **低空观测因子**
4. 拖动 **人流/POI/交通** 滑条，观察格网即时变色
5. 勾选 **纳入无人机项**，对比加成效果
6. 点击 **重新运行 / 全量** 触发后端模型（或 mock 回退）
7. 右栏查看 **因子贡献** 与 **TOP6**，点击排名定位热点
8. 需要区县级概览：图层树开启 **行政区汇总面**
9. 需要 POI 底图：勾选 **商业 POI 样点**

## 十二、已知限制与后续

| 项 | 说明 |
|----|------|
| 智眼数据 | 仍为 **模拟观测点**，非政务智眼生产库 |
| 格网精度 | 750m 示意格网，非官方统计格网 |
| 后端模型 | 演示环境走 fixtures；失败时仅保留本地计算 |
| 格网体量 | 3908 格全量渲染，低端设备缩放/拖动可能略卡 |
| 权重即时算 | 拖动滑条不推送任务条，仅「运行/同参重算」入队 |
| 与总览差异 | 总览用区面 choropleth；本页默认 **格网精细尺度** |
